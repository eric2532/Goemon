Forest Shrine v2.59.0 — denser spawns and Explorer close attack assist
2026-10-15, macOS Apple M3, Godot 4.6.1 Forward+/Metal

Changes
- Three arrivals each 0.65-second timer, after the existing two-second opening.
- Finite waves: 72, 108, 144, 180, 240. Active cap 240; bounded spawn retries.
- Southern entry and fog clearance retained. Ordinary batch members spaced apart.
- One Daruma in each of waves 3–5, preserving the giant's role and staging.
- Crowd-only textures limited to 1024px with mipmaps. Original source images,
  character rendering and the hub remain sharp. Ordinary crowd shadows disabled;
  Daruma retains shadows. Reuse pose images/textures and update changed rows only.
- Normal transforms computed once per part instead of inverse per vertex.
- Explorer primary chooses an aimed, living, visible target within 2.75m of its
  fitted body surface and the original forward half-plane. Turns during windup
  and redirects the existing short forward lunge; lateral dodge is retained.
- No extra damage, range, lunge distance, cooldown or teleport. Physics and walls
  remain authoritative; loss of visibility or target validity ends assistance.

Performance method
Same real scene, 80 then 240 visible ordinary enemies, identical wide orthographic
camera. Paired runs compare saved pre-change crowd/wave/shader files against new
files. CPU components are separately sampled. Static frame samples keep walking
poses moving; live samples additionally tick AI, actor colliders and world sync.
These are local stress measurements, not a guaranteed framerate on other hardware.

80 visible enemies: live median 16.65 -> 16.68ms; p95 17.16 -> 16.99ms.
Drawn primitive passes 10,095,507 -> 3,918,773; crowd update 1.90 -> 0.59ms.

240 visible enemies: live median 46.34 -> 25.95ms; p95 93.27 -> 75.48ms.
Drawn primitive passes 28,553,328 -> 10,071,224; crowd update 5.50 -> 2.74ms.

Limits: the deliberately all-visible 240-enemy case still exceeds 16.67ms and has
occasional spikes. Rendering savings do not remove the CPU cost of three times as
many active actors. Typical camera views contain fewer enemies. Raw metrics and
screenshots: before-final/ and after-final/; profiler: tests/forest-shrine/dense_crowd_profile.gd.
