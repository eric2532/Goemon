# In-game map builder

User approved an in-game builder after the explanation of modular pieces, grid snapping, placement, rotation, deletion, gameplay markers, saving and Play Map. User also requested new assets. Work only in latest Fire Siege worktree, preserving v2.42 Ranger and all prior work.

Deliver a full-screen map editor accessible from main menu. Isolated top-down 3D preview, palette grouped into ground/structures/nature/gameplay, place/select/move/rotate/duplicate/delete, 1/2/4m snapping, undo/redo, pan/zoom, named local save/load, starter and blank layouts. Single editable route runs from enemy entrance through ordered waypoints to base; moving these updates the road. Show marker order and allow reordering. Flat 160×310m map initially. New native mesh assets: torii, pavilion, stone lantern, fence, stone wall, bamboo, cherry tree, cedar, rocks, supply crates and banner plus grass/sand/stone tiles and road. Collision authored once in the piece catalog and shared by validation and play.

Map document schema 1 with title and array of typed pieces (uid, kind, x, z, rotation). Singleton hero spawn, enemy entrance and base. Bounded file size/object count and strict schema validation. Invalid loads preserve current draft. Named saves atomic, with save failure shown. Confirmation before discarding unsaved edits. Play validates clear routes and safe spawns, then launches ordinary Fire Siege with all heroes; pause menu returns to editor with draft intact. Standard Fire Siege remains available and unaffected. Custom routes support arbitrary directions and recovery after knockback. Saved JSON lives in game user maps directory and needs no external editor.

Validate document round trips and malformed inputs; editing history; blocking collisions; scene marker conversion; real custom enemy routing and structures; input/UI save/load/play/return; source and packaged regressions. Render screenshots to inspect layout and new assets. Export only Fire Siege macOS as v2.43, back up v2.42 before replacing latest app.
